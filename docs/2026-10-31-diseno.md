# marketing-lab-mcp: diseño v0.1.0

Fecha: 2026-10-31. Estado: borrador para aprobar.

## 1. La idea

Un servidor MCP de marketing. MCP (Model Context Protocol) es la forma estándar de darle herramientas a una IA como Claude.

El servidor tiene 9 herramientas de decisión de marketing: tests A/B, email, presupuesto, e-commerce y atribución. Trabajan con datos públicos reales (y una base simulada), y también aceptan los números del usuario.

Cualquier persona lo puede probar de tres formas, sin pagar nada:

1. **En la página**, sin instalar nada: un playground y 4 charlas grabadas con Claude.
2. **En su propio Claude**: pega una URL pública en claude.ai (también en el plan gratis).
3. **En su compu**: lo corre desde el código fuente.

## 2. Por qué este proyecto (el hueco)

Relevamiento del 2026-10-31 (estrellas y versiones de GitHub, npm y PyPI). Fuentes principales: [aaj-engines](https://github.com/sarojkjha/aaj-marketing-skills), [abtestresult-mcp](https://abtestresult.com/mcp-server), [mcp-server-meridian](https://pypi.org/project/mcp-server-meridian/), [GA4 MCP](https://github.com/googleanalytics/google-analytics-mcp), [Klaviyo MCP](https://developers.klaviyo.com/en/docs/klaviyo_mcp_server). Resumen:

| Grupo | Ejemplos | Qué les falta |
|---|---|---|
| Servidores de las marcas | GA4, Google Ads, Meta Ads, Klaviyo, HubSpot, una plataforma de e-commerce latinoamericana (Admin MCP) | Todos piden cuenta. Ninguno tiene demo pública. |
| Servidores de MMM | `mcp-server-meridian`, `pymc-marketing-mcp` | Hay que instalar Python y tener un modelo entrenado. Sin demo. |
| Cálculos sin cuenta | `aaj-engines`, `abtestresult-mcp`, `rigor-mcp` | Casi todos solo test A/B. Sin playground. `aaj-engines` esconde 66 cálculos detrás de una sola herramienta genérica. |

Lo que nadie tiene y este proyecto sí:

- Atribución multi-touch (Markov y Shapley) como herramienta MCP.
- Herramientas tipadas, una por decisión, con descripciones que la IA entiende sola.
- Datos públicos reales, no números de juguete.
- Playground en el navegador con la misma lógica del servidor, más charlas grabadas reproducibles.
- Tests y CI visibles.

Lo que tiene menos: menos cálculos que `aaj-engines`. No entrena un MMM: usa el del repo `marketing-mix-model`.

## 3. Las 9 herramientas

Nombres y descripciones en inglés: los lee la IA.

| Herramienta | Qué responde | Datos de ejemplo | Acepta datos propios |
|---|---|---|---|
| `ab_test_evaluate` | ¿Ganó B? Diferencia, intervalo, p-valor, probabilidad bayesiana de que B sea mejor, chequeo de reparto (SRM). | Hillstrom | Sí: visitas y conversiones por grupo |
| `ab_test_plan` | Cuánta gente por grupo y cuántos días hacen falta. | — | Sí: tasa base, efecto mínimo, tráfico diario |
| `email_test_analyze` | Resultado del test de email por grupo y segmento: visitas, compras, gasto, uplift. | Hillstrom (64 mil clientes) | No |
| `budget_simulate` | Ventas esperadas de un reparto entre canales, con rango. | Robyn vía `marketing-mix-model` | Sí: el reparto |
| `budget_optimize` | Mejor reparto para un total semanal, con límites por canal. | Robyn vía `marketing-mix-model` | Sí: total y límites |
| `store_sales` | Ventas por categoría, estado y mes. Reseñas y entregas tarde. | Olist (100 mil pedidos) | No |
| `customer_rfm` | Segmentos de clientes por recencia, frecuencia y monto. | Olist | Sí: lista de clientes (con tope) |
| `lead_funnel` | Qué canal de origen trae leads que cierran, y cuánto tardan. | Olist Marketing Funnel (8 mil leads) | No |
| `attribution_compare` | Compara último clic, primer clic, lineal, Markov y Shapley. Con datos simulados muestra cuál se acerca a la verdad. | Recorridos simulados con verdad conocida | Sí: recorridos (con tope) |

Reglas para todas:

- Entradas validadas con esquemas (zod). Si algo falta o está mal, el error dice qué corregir.
- Topes de tamaño en las entradas, para entrar en 10 ms de CPU de Cloudflare.
- Cada respuesta trae un texto corto para la IA y los datos estructurados para la página.

## 5. Arquitectura

Un solo núcleo en TypeScript, usado en 3 lugares:

```
data/*.json  ─┐
              ├─ core/ (cálculos puros, sin red)
              └─ server/ crea el McpServer con las 9 herramientas
                     ├─ Navegador: playground (InMemoryTransport)
                     ├─ Cloudflare Worker: URL pública /mcp (Streamable HTTP, sin estado)
                     └─ Local: stdio (node)
```

- SDK: `@modelcontextprotocol/server` v2 (spec 2026-07-28), versión fija.
- Worker: `createMcpHandler`, sin estado. Sin base de datos, sin KV, sin Durable Objects, sin claves en ejecución.
- Los datos van dentro del bundle como JSON.
- Prepara: `prep/` en Python. Núcleo y servidor: `src/`. Página: `site/`.

## 6. La demo en vivo

Una página en GitHub Pages, en inglés con resumen en español:

1. **Arriba**: qué es, en una oración, y la URL para pegar en Claude.
2. **Charlas grabadas** (4): se reproducen paso a paso. Cada llamada a una herramienta tiene un botón "Run it live" que la vuelve a correr.
   - 🇬🇧 Test de email: ¿funcionó y para quién? (`email_test_analyze`, `ab_test_evaluate`)
   - 🇬🇧 Reparto de 41 mil dólares semanales (`budget_simulate`, `budget_optimize`)
   - 🇬🇧 Último clic contra Markov (`attribution_compare`)
   - 🇦🇷 Categorías que más venden y clientes por perderse (`store_sales`, `customer_rfm`, `lead_funnel`)
   - Las graba Claude Code conectado al servidor real. Se guardan como JSON en el repo.
3. **Playground**: elegir herramienta, completar el formulario, ver la respuesta y el mensaje MCP crudo (JSON-RPC). Botón para correr en el navegador (por defecto) o en el servidor en vivo. Si el servidor falla, avisa y vuelve al navegador.
4. **Conectalo a tu Claude**: pasos para claude.ai (conector personalizado, sirve en el plan gratis), Claude Desktop, correrlo local, y referencia del conector MCP de la API de Claude para desarrolladores.

El diseño visual se define en la fase 2 (skill `frontend-design`), para que no parezca plantilla.

## 7. Hosting y por qué cuesta 0

| Pieza | Dónde | Límite gratis | Tarjeta |
|---|---|---|---|
| Página y playground | GitHub Pages | 1 GB de sitio, 100 GB por mes | No |
| URL pública `/mcp` | Cloudflare Workers Free | 100 mil pedidos por día, 10 ms de CPU por pedido | No (verificar al crear la cuenta) |
| CI | GitHub Actions | Gratis en repos públicos | No |

- La IA la paga cada visitante con su propia cuenta de Claude. La demo pública nunca llama a la API de Claude.
- Si alguien abusa de la URL, Cloudflare corta hasta el día siguiente. Nunca cobra.

## 8. Que siga andando solo

- Sin claves en ejecución, sin bases de datos, sin tareas programadas.
- Datos fijos dentro del repo: no dependen de que las fuentes sigan online.
- Versiones fijas de dependencias.
- El deploy del Worker usa un token de Cloudflare **sin vencimiento**, solo con permiso de Workers, guardado en los secrets de GitHub. Si el token falla, el servidor sigue andando. Solo se frenan los deploys nuevos.
- Si Cloudflare falla, la página sigue andando en modo navegador.

## 9. Tests y CI

- TDD con vitest en el núcleo. Los valores esperados salen de librerías de referencia en Python (scipy, statsmodels) y se guardan como fixtures.
- Tests de contrato: un cliente MCP en memoria llama a cada herramienta y valida la respuesta.
- `budget_simulate` se compara contra los casos de prueba del simulador de `marketing-mix-model`.
- pytest para los scripts de `prep/`.
- CI en GitHub Actions: lint, tipos, tests, build de la página y del Worker. Deploy a Pages y a Cloudflare al pasar `main`.
