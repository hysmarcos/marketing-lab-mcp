# marketing-lab-mcp v0.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public MCP server with 9 marketing decision tools, a no-install demo page on GitHub Pages and a free stateless `/mcp` URL on Cloudflare Workers.

**Architecture:** Pure TypeScript calculations in `src/core/` read small JSON summaries in `data/`. One `createServer()` factory registers the 9 tools and runs in three places: in the browser (in-memory transport, for the playground), on a Cloudflare Worker (stateless Streamable HTTP) and locally over stdio. Python scripts in `prep/` turn raw public datasets into the JSON summaries once, by hand, and also write reference values that the TypeScript tests check against.

**Tech Stack:** TypeScript, `@modelcontextprotocol/server` and `@modelcontextprotocol/client` 2.4.0 (spec 2026-07-28), zod 4, vitest, Biome, Vite, Wrangler. Python 3.12 with uv, pandas, scipy, statsmodels, pytest. GitHub Actions, GitHub Pages, Cloudflare Workers Free.

**Spec:** `docs/2026-10-31-diseno.md` (in Spanish). Research with sources: `docs/2026-10-31-relevamiento.md`.

## Review Focus

1. Rates of 0 or 1 in an A/B test (0 conversions, or conversions = visitors): no `NaN` or `Infinity` in any output; the result carries a warning that the approximation is weak. Test in Task 1.
2. Budget plans with an unknown channel, a negative value or spend above the observed weekly maximum: unknown or negative is rejected with the list of valid channels; above the maximum is allowed but flagged `out_of_range`. Test in Task 4.
3. Attribution input with zero total conversions, more than 12 channels or a single channel: zero conversions gives all-zero credit with a warning, not `NaN`; more than 12 channels is rejected; one channel gets 100%. Test in Task 9.
4. Filters that match nothing (unknown state, unknown category, empty month range) in `store_sales`, `customer_rfm` and `lead_funnel`: an empty result with a message that lists valid values, never a crash. Tests in Tasks 6, 7, 8.
5. Live server unreachable, slow or blocked by CORS while the visitor uses "Live server" mode: the playground shows a notice and switches back to "In your browser". Test in Task 13.

## Shared Interfaces (defined in Task 2, used everywhere)

```ts
// src/server/tool.ts
export class ToolInputError extends Error {}           // domain error: message goes back to the caller
export interface ToolSpec<I extends z.ZodObject = z.ZodObject, O extends Record<string, unknown> = Record<string, unknown>> {
  name: string;                 // snake_case, e.g. "ab_test_evaluate"
  title: string;                // human title for the page
  description: string;          // for the LLM: what it answers, when to use it, data source, limits
  input: I;                     // zod schema; every field has .describe()
  run(args: z.infer<I>): O;     // pure, synchronous
  summarize(out: O): string;    // plain-English summary for the LLM, <= 1200 chars
  examples: { label: string; args: z.infer<I> }[]; // >= 1; used by tests and playground presets
}
// src/server/tools/index.ts
export const TOOLS: ToolSpec[];  // the 9 tools, in the order of the spec table
// src/server/createServer.ts
export function createServer(): McpServer;
```

Tool result shape (every tool): `{ content: [{ type: "text", text: summarize(out) }], structuredContent: out }`. A `ToolInputError` or zod failure becomes `{ isError: true, content: [{ type: "text", text: <message> }] }`. Every output object includes `warnings: string[]` (empty when none) and `source: string` (dataset name and license, or `"user input"`).

### Task 9: Simulated journeys and `attribution_compare`

**Files:**
- Create: `prep/journeys.py`, `prep/tests/test_journeys.py`, `data/journeys_sample.json`, `src/core/attribution.ts`, `src/server/tools/attribution_compare.ts`
- Test: `tests/core/attribution.test.ts`

**Interfaces:**
- `journeys_sample.json`: `{ source: "simulated, seed 42", channels: string[], truth: Record<string, number> /*shares, sum 1*/, journeys: [{ path: string[], conversions: number, nulls: number }] }`, aggregated by unique path.
- `compareAttribution(args: { journeys?: Journey[] /*max 5000 rows, path length 1–20*/ }, sample): { channels, total_conversions, models: { last_touch, first_touch, linear, markov, shapley }: Record<string, { credit: number; share: number }>, truth: Record<string, number> | null, error_vs_truth: Record<model, number> | null /*mean absolute error of shares*/, warnings, source }`.

Generator rules (`journeys.py`, `numpy.random.default_rng(42)`, 20,000 users):
- Channels: `display, paid_social, paid_search, email, organic_search, direct`.
- Path length: 1 + Poisson(2), capped at 8.
- First touch draws from display .35, paid_social .30, paid_search .15, organic_search .15, email .03, direct .02.
- Last touch (paths of length ≥ 2) draws from direct .35, email .25, organic_search .20, paid_search .15, paid_social .03, display .02.
- Middle touches are uniform.
- `p(convert) = 1 − 0.99·∏_{c ∈ set(path)} (1 − e_c)` with e = display .06, paid_social .05, paid_search .04, email .03, organic_search .02, direct .005. Draw the outcome as Bernoulli.
- `truth_c = Σ_users (p − p_without_c)`, normalized to sum 1. This is the counterfactual removal effect: write that definition in `data/README.md`.

Model rules (TS):
- `last_touch` and `first_touch`: the whole conversion goes to that touch.
- `linear`: equal split over every touch, repeats included.
- `markov`: first-order chain with `start`, the channels, `conv` and `null`; consecutive repeats collapse. Removal effect of c = 1 − P(conv without c)/P(conv), where removing c sends its node to `null`. Credit = total conversions × RE_c / Σ RE. Solve the absorbing probabilities with Gaussian elimination and partial pivoting.
- `shapley`: v(S) = conversions of journeys whose channel set ⊆ S, exact over all subsets.

- [ ] **Step 1: pytest.** Display has a higher truth share than last-touch share; direct has a higher last-touch share than truth share. The overall conversion rate is between 8% and 25%. Each truth share is between 0 and 1, and the shares sum to 1 within `1e-9`.

  - last_touch A 0, B 2. first_touch A 1, B 1. linear A 0.5, B 1.5. shapley A 0.5, B 1.5. markov A 0.5, B 1.5 (removal effects A 1/3, B 1).
